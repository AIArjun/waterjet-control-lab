Simulation API.

One isolated, temporary simulation per anonymous session.

The client advances simulation time explicitly. This API has no hardware interface and does not provide a wall-clock control service.

Start a session

POST /api/sessions
→ {"session_id": "…", "state": {…}, "scenarios": {…}}

Use the returned ID for every request below. It acts as a temporary capability: do not share it. Sessions expire after 30 minutes of inactivity. The demonstration accepts at most 64 sessions.

Advance the controller

POST /api/sessions/{id}/tick
{"command":{"surge":0.0,"turn":0.0,"control":"manual","heading_deg":0},"scans":2}

Each scan is 50 ms of simulation time. The scan count is an integer from 1 to 20. Surge and turn are normalized to [-1, 1]. Heading is [0, 360). Control mode is manual or heading. The command heartbeat is received once before the requested scans.

Operator actions

POST /api/sessions/{id}/action
{"action":"arm"}

Allowed actions: arm, run, stop, reset, estop, release_estop. Check the returned accepted flag and state. Rejected actions do not bypass the controller's interlocks.

Faults and scenarios

POST /api/sessions/{id}/fault
{"fault":"low_pressure","enabled":true}

POST /api/sessions/{id}/scenario
{"name":"heading"}

POST /api/sessions/{id}/wind
{"east_n":100,"north_n":0}

Faults: low_pressure, overheat, comms_loss, sensor_dropout, port_stuck. Scenarios: harbor, heading, pressure, watchdog, estop. Wind components are bounded to ±1000 N. Loading a scenario replaces only that session's simulation.

Read and export

GET    /api/sessions/{id}
GET    /api/sessions/{id}/history
GET    /api/sessions/{id}/export.csv
DELETE /api/sessions/{id}
GET    /healthz

Telemetry is retained at 10 Hz for approximately ten minutes. Exports also include the current state, including a trip between scheduled samples. The event journal holds the most recent 200 events.
